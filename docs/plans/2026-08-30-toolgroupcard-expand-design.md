# ToolGroupCard 分级展开设计（思考过程 / 工具调用）

> 目标：长思考 + 多工具不再顶满屏幕；展开时直接落在"最新"处；工具默认只露最新一个，
> 再点一次才铺开全部工具详情。

## 1. 背景

聊天显示模式有两种：`flat`（默认，每个 part 平铺）/ `grouped`（连续「思考 + 工具」
聚合为一张 `ToolGroupCard`）。本次**只改 `grouped` 模式的 `ToolGroupCard`**。

现状问题：`ToolGroupCard` 默认折叠，一旦展开就把**全部思考 Markdown + 每个工具一行**
一次性渲染出来，长思考/多工具时直接顶满屏幕，既看不到上下文也没法快速定位到"现在在干嘛"。

## 2. 需求（已与用户逐条确认）

1. 展开后内容装在**固定高度的框**里（≈ 屏高 1/3），框内可滚动，不撑爆屏幕
2. 展开时**跳到最新内容**（思考末尾 / 最新工具）
3. 工具默认**只显示一个**：**正在运行的优先**，没有在跑的才显示最后一个
4. **再点一次**才铺开全部工具调用详情（不限高）
5. 进行中（AI 还在思考/跑工具）**保持折叠**，但标题栏实时反映进度
6. 二级展开的入口是**框内底部的按钮**（不是再点标题栏）

## 3. 方案选择

| 方案 | 一级展开 | 看历史思考 | 技术风险 |
|---|---|---|---|
| **A. 限高 + 框内 ScrollView**（采用） | 屏高 1/3，框内可上下滚 | ✅ 能往上翻 | 中：FlatList 内嵌垂直 ScrollView 的嵌套滚动手势 |
| B. 截断 + 渐隐遮罩 | 固定 1/3 高，超出截断 | ❌ 只看得到末尾 | 低 |
| C. 二级改全屏 Modal | 同 A | ✅ | 中：上下文切换 |

选 A：用户诉求"一定高度的方框内显示内容"本身就要求框内可翻看；B 让限高失去意义。
嵌套滚动靠 `nestedScrollEnabled` + 边界联动解决（真机验证）。

## 5. 状态机

| 当前 | 动作 | 结果 |
|---|---|---|
| 0 折叠 | 点标题栏 | → 1（限高，滚动到最新） |
| 1 限高 | 点标题栏 | → 0 |
| 1 限高 | 点底部入口 | → 2 |
| 2 全开 | 点标题栏 | → 0（不回 1） |

三个状态，不循环。状态放在组件内 `useState`。

## 6. 一级展开细节

**框内内容顺序**：思考（Markdown 全文，滚动查看） → 单个工具行（glance 样式，不可点）。

**"最新一个工具"的挑选**：
```
1. 有 status ∈ {called, progress}（运行中）→ 取其中最后一个
2. 否则 → 取列表最后一个
3. 无工具 → 工具区留空
```

**滚动到最新**：
- 展开（0→1）：布局完成后 `scrollToEnd({ animated: false })`，不做动画
- 流式输出期间：内容变化后**仅当距底 ≤ 24pt** 才自动跟随；用户手动上翻时**不打断**；翻回底部恢复跟随
- 跟踪方式：`onScroll` 计算 `contentSize.height - layoutMeasurement.height - contentOffset.y`

**嵌套滚动**：`nestedScrollEnabled`（Android 必需）；框内未到边界时手势不外传。

**内容不超框高**：取消 `maxHeight`，按自然高度显示，配 `LayoutAnimation` 平滑过渡。
（初始按限高渲染，`onContentSizeChange` 测得较矮后取消限高。）

## 7. 二级展开细节

- 不限高，随页面滚动
- 思考全文 + **全部工具按调用顺序**渲染
- 每个工具用 `ToolPart`（`BasicTool.tsx`）渲染详情，传 `defaultExpanded={true}`：
  `ToolPart` 原为 `useState(false)` 默认折叠，不改的话"展开详细"名不副实
- `defaultExpanded` 只是初值，用户仍可单独点一下收起某条（应对超长 bash 输出）
- 二级下不显示底部入口

## 8. 底部入口按钮

| 工具数 | 文案 | 显示 |
|---|---|---|
| 0（纯思考） | — | 不显示 |
| 1 | 「查看详情」 | 显示 |
| > 1 | 「展开全部 (N)」 | 显示 |

（因为工具行不可点，单工具时也必须留入口，否则看不到该工具的详情。）

## 9. 流式 / 进行中

- 进行中**不自动展开**；标题栏实时反映进度（现有 `statusIcon` + 计数已支持）
- 已展开（level 1）时按第 6 节的跟随规则处理
- 工具状态从"运行中"变"完成"导致显示的那一行切换时，同样遵守跟随规则

## 10. 边界情况

| 情况 | 处理 |
|---|---|
| 内容没超过框高 | 取消限高，自然高度 |
| 纯思考无工具 | 框内只有思考，无底部入口 |
| 只有 1 个工具 | 入口文案「查看详情」 |
| 二级下某条输出超长 | 单独点该条收起 |
| 滚出屏幕再滚回来 | 回到折叠态（FlatList 回收，组件 state 丢失） |
| 屏幕旋转 | 用 `useWindowDimensions()` 自动重算框高 |

**已知取舍**：不做跨回收的展开状态记忆（YAGNI）。若用户反馈"滚走再回来就折叠"很烦，
再考虑把 level 提到 store（按 messageId + blockKey 记忆）。

## 12. 测试计划

`ToolGroupCard`：
- 折叠态只渲染标题栏
- 点标题 → level 1：渲染思考 + 恰好 1 个工具
- 运行中优先：构造 [已完成, 运行中] → 显示运行中那个
- 无运行中 → 显示最后一个
- 入口文案：N>1「展开全部 (N)」/ N=1「查看详情」/ N=0 不显示
- 点入口 → level 2：全部工具渲染，`ToolPart` 收到 `defaultExpanded=true`
- level 2 点标题 → 回到 level 0

`ToolPart`：
- `defaultExpanded=true` 时详情可见
- 点击可收起（默认展开不剥夺折叠能力）

回归：`MessageItem` grouped 用例、`chatComponents` 用例、全量测试、`tsc` 与基线一致。

## 13. 风险

- **嵌套滚动手势**：框内滑动误滚外层列表。缓解：`nestedScrollEnabled` + 真机验证
- **FlatList 回收**：展开状态丢失（见第 10 节已知取舍）
- 手机上生效需重打 JS bundle 再装 APK
